# 「我遲到了」切分反例的實際原因（2026-10-14）

正確切分與候選一直存在。模型 0.5 的完整解碼將「我遲到了」列在第三名，
但首選仍是「握到了」。實際無法補救的判斷來自開發 CLI 的模擬修正者：
句號後的候選視窗顯示標點選單，修正者沒先關閉它，便進入游標詞補救。
沿著「握／到了」切分的詞游標找不到「我／遲到／了」，因此錯判不可修復。

逐鍵重放反證了先前「正確切分消失」與本輪最初的穩定鎖定猜測。按一次
Esc 只關閉標點選單，沒有重新解碼、改寫按鍵或取消已選詞，整句第三候選
就可見。因此這輪只修正評估流程，沒有調模型、切分、穩定前綴或 adapter。

## 重現

既有純合成 trace：`2jo41jfu3，jit42l4xk7。`，期望「對不起，我遲到了。」。
其中 `ji` 沒聲調、`t4` 的聲調錯誤，由 tone tolerance 保留「遲」；另一條
單音節路徑將 `jit4` 修復成「握」。模型首選採用後者，但四音節路徑仍在。

```sh
MISSTYPE_WORD_LM="$PWD/.cache/wordlm/pilot.bin" MISSTYPE_WORD_LM_WEIGHT=0.5 \
  core-zig/zig-out/bin/misstype-dev \
  --session-trace '2jo41jfu3，jit42l4xk7。⎋↓d' --show --show-candidates
```

句號後列出「。」「．」「…」等標點。Esc 後整句列表前三名為：

1. 對不起，握到了。
2. 對不起，我吃到了。
3. 對不起，我遲到了。

Down 啟用選字，`d` 選第三列，Return 可送出正確句子。此手動重放不需要
`expected` 或模擬器介入，也確認核心已有可行的真實按鍵路徑。

## 修正與測試

`misstype-dev` 的 `correct` 在已發現文字不符且標點選單仍開啟時，先送出
真實 Esc，再沿用第一頁整句選字規則。Esc 計入 `fix_keys`；文字原本正確
時不關選單或增加補救按鍵。既有首選、原始輸入、最多選 16 次、整句只查
第一頁、游標詞補救與不可回收的 auto-commit 限制保持原定義。

新增兩個原生開發 CLI 測試，納入 `zig build test`：

- 小型合成詞庫將 `jit42l4xk7。` 顯示成「握到了。」。舊修正者不能恢復；
  新修正者能用 Esc、Down、選字鍵三個補救按鍵送出「我遲到了。」。
- 原本正確的 `su3。 → 你。` 不增加補救選字或按鍵。

測試不依賴約 170 MB 的詞模型或本機公開語料。macOS 與 Docker Linux
皆通過 271 個核心測試與兩個開發 CLI 測試；Python 100 個測試通過。
沒有核心或平台行為改動，不重寫解碼／session golden，也沒有 GUI 測試。

## 評估結果與可比性

修正後，正式預設全部 7,200 案例的首選與最終文字不變，選字成本
FIXED 0／BROKEN 0。38 個案例的補救按鍵數變動：20 個增加、18 個減少，
總按鍵淨減 77。增加通常是補計 Esc；減少來自直接選整句、少走游標。
已更新 baseline 的補救成本與 metadata，不能將它稱為解碼品質改善。

同一模型、同一權重 0.5、相同排序／分批的 3,616 個 dev 案例：

| 指標 | 正式預設 | 模型 0.5 |
| --- | ---: | ---: |
| 首選正確句子 | 2,479 | 2,644 |
| 不可修復句子 | 665 | 647 |
| 可修復句子的選字次數 | 526 | 328 |
| 選字改善／退步案例 | 基準 | 251／56 |
| 部分聲調錯字組不可修復 | 42 | 42 |

先前模型的 648 個不可修復句子降至 647，就是恢復此例的整句補救。
無錯字對照的首選不變。固定 0.5 現在通過既定的各 track/persona 守門，
不代表其排名、容量或啟動成本已適合產品，也不是獨立泛化驗證。
[精簡結果](../tools/eval/word_lm_menu_fix_v1.json) 記錄模型、資源、執行檔雜湊
與 `punctuation-escape-v1` 修正 protocol。

`typing_eval.py` 保存結果時記錄此 protocol，`eval_word_lm.py --summarize`
會拒絕把舊修正流程的已保存 profile 當成新評估。核心的每鍵路徑不變；
模擬補救時間／按鍵成本有變，不能從這輪時序數字宣稱引擎加速。
外部封存的 200 句仍未解碼；下一步應固定這個 protocol 做獨立外部確認，
不再以此反例尋找模型權重。
