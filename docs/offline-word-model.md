# 離線詞級模型原型（2026-10-14）

完整詞級 bigram 在既有開發集有實質收益，但尚未通過採用門檻。
權重 0.5 減少選字的案例 252 個、增加 57 個；有錯字的部分聲調組卻多一個
不可修復案例。產品預設不變，封存的 200 句外部測試仍未使用。
這是開發結果，不是新的獨立泛化證據。

## 方法與資料

先固定假設：把完整條件機率放進詞路徑搜尋，能否減少無聲調選字，同時
保護每種打字 persona 的可修復率與無錯字對照的正確率。
`tools/word_lm.py` 讀取四個本機 HPLT 分片，每份前 10,000 文件；分片與分詞
詞庫雜湊都須符合 `third_party/HPLT/sources.json`。使用既有詞庫 DP 分詞，
完整計數所有詞對，保留低頻項，加入 BOS、EOS、UNK。舊的同音 PMI 表有
歧義篩選與低頻截斷，沒有被當成完整條件機率。

共 47,640,392 個目標詞元（包含 8,395,282 個 EOS）、8,390,810 種詞對，
107,354 個模型符號，其中 93,408 個目標符號被觀察到；UNK 占目標詞元
1.39%。二進位大小 169,963,312 bytes。輸入與模型 SHA256、固定權重及
精簡結果保存在 [word_lm_pilot_v1.json](../tools/eval/word_lm_pilot_v1.json)。
模型本體與生成資料留在忽略的 `.cache/`。

固定折扣 D=0.75、unigram 加一平滑，BOS 不屬於目標詞彙 V：

```text
Puni(w) = (c(w) + 1) / (sum c(w) + |V|)
P(w|h) = max(c(h,w) - D, 0) / c(h)
         + D * distinct_next(h) / c(h) * Puni(w)
```

沒有歷史計數時回退至 Puni。未知詞映射 UNK。所有純漢字片段都加入
BOS/EOS，但互動解碼只用 BOS，不替每個尚未完成的輸入前綴加 EOS 分數。
Zig 搜尋中的語言項是 `(1-alpha) * lexicon_score + alpha * log P(w|h)`，
原修正成本、每詞成本 0.5、學習與鎖定項保持原定義。詞庫分數是 heuristic，
這是分數內插，不能稱為兩個正規化模型的機率內插。
啟用後替代搜尋後的同音 PMI 加分；權重零時完全保留原行為。

只測事先指定的 alpha 0.1、0.25、0.5；同一順序、分組、兩個種子，共
3,616 個真實 Zig Session 模擬案例，包含有聲調、無聲調、部分聲調、錯字
與三種中英混打方法。守門按 track 與 persona 分別檢查，不能讓一組的
改善抵消另一組的損失。既有 holdout 沒有用來挑權重。

## 開發結果

| alpha | 減少選字案例 | 增加選字案例 | 可修復句子的總選字次數 | 通過門檻 |
| --- | ---: | ---: | ---: | --- |
| 原預設 | 0 | 0 | 523 | 是（基準） |
| 0.1 | 51 | 179 | 646 | 否 |
| 0.25 | 190 | 68 | 396 | 否 |
| 0.5 | 252 | 57 | 325 | 否 |

選字總數只涵蓋可修復句子，因此採用時必須同時保護可修復率。
0.5 的全批不可修復句子 668 → 650，但部分聲調錯字組 44 → 45，
包含兩個新失敗與一個新成功。整體平均收益不能抹去這個退步。

| 無錯字純中文首選正確率 | 原預設 | alpha 0.5 |
| --- | ---: | ---: |
| 有聲調 | 91.0% | 92.4% |
| 無聲調 | 77.2% | 81.4% |
| 部分聲調 | 83.4% | 88.3% |

可重放反例與候選前後分數見 [word-model.md](../tests/fixtures/word-model.md)。
例如漏打一鍵的「公車還沒來」，完整解碼仍有正確第二候選，但實際 Session
補救流程無法送出它。接下來應調查選字範圍與候選切分如何造成這個落差，
先保持已有的修復途徑，再驗證模型收益；這輪沒有靠追加權重消除失敗。

## 延遲與容量

完整 dev 使用八個 worker，延遲受資源競爭影響。另以相同的前 24 句 dev、
八個 persona、兩個種子，單 worker 重放 384 個案例／7,113 個按鍵（可用
`tools/eval_word_lm.py --bin .cache/wordlm/bin/misstype-dev --latency` 重跑）：

| 指標 | 原預設 | alpha 0.5 |
| --- | ---: | ---: |
| 每鍵平均 | 1.15 ms | 4.07 ms |
| p95 | 5.88 ms | 19.34 ms |
| 本批最慢按鍵 | 67.72 ms | 137.57 ms |
| 啟動＋一次短解碼 | 133.6 ms | 7,346.7 ms |

啟動數字是檔案快取暖機後的新程序，包含載入／驗證與一次 `su3` 解碼，
不是清空系統快取後的冷啟動。原型保留完整約 170 MB 計數，並在複製前後
驗證表；載入與容量目前不適合直接接入 IME。所有結果是本機離線解碼，
沒有 Transformer、LLM 或遠端服務。

初次並行驗證被 golden 腳本改建的 Debug CLI 污染，整批排除；採用上述
獨立 ReleaseFast 執行檔的成對重跑。評估工具記錄執行檔雜湊，並在每批
前後檢查是否被改建。`--summarize` 只重算已保存結果，沒有再次解碼。

## 驗證與限制

Zig 單元與行為測試通過；1,344 個候選 golden、43,152 個完整 metadata／
touch／Unicode golden、四組 session replay golden 全部一致。
正式預設 dev 對既有 typing baseline 是 FIXED 0／BROKEN 0。
Python 既有 96 個測試與新增四個模型／評估守門測試通過；C ABI CLI 11 個
測試、Linux fcitx5 C1–C15 與 IBus headless、wasm playground 都通過。
沒有 adapter/UI 改動，也沒有進行 GUI 手動測試。

分詞承襲詞庫偏好，前 40,000 篇網頁不是隨機抽樣。訓練資料與開發／封存
測試的重疊尚未逐句查核；尚有 beam 與每 reading 詞數上限，沒有人工驗證
的真實鍵盤記錄。現有 dev 已反覆使用，不能據此宣稱找到泛化的「聖杯」。
此原型作為停用的開發實驗保留；先處理修復可達性與載入成本，通過固定
門檻後，才能動用新的外部測試。
